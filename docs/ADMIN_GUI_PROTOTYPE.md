# 管理GUI試作の使い方と実装範囲

更新: 2026-10-04。devで[管理GUI計画](ADMIN_GUI_PLAN.md)の段階AとBの一部を実装。現在の管理画面の代替となる操作モデルを、架空データで検証する独立した試作。通常のindex.htmlからは読み込まない。

## 開く方法

アプリのリポジトリルートで次を実行し、表示されたURLをブラウザで開く。

```powershell
node scripts/preview-admin.mjs
```

停止はCtrl+C。静的ホストでも `/prototypes/admin/index.html` から開ける。ES modulesを使うため、HTMLファイルをfile://で直接開かずHTTPサーバー経由で確認する。

## 操作できる範囲

- 共通の5領域ナビ。PCでは左側、狭い画面では現在の領域名が付いた開閉メニュー。
- 名簿の全件/グループ別表示、氏名・所属・内線検索、結果件数と条件解除。
- メンバーの登録/編集、所属選択、個人/複数人の所属変更。移動先末尾へ元の表示順で追加。
- グループの追加/名称変更、グループ内の人員順・グループ表示順の上下/位置指定。検索中は確認して全件表示へ戻してから並び替え。
- 所属メンバーを別グループへ移してからグループ削除。人員削除は別の確認操作。
- 一つの名簿下書き、最終状態の差分一覧、破棄、試作内の確定。入力中の値を黙って確定対象から除外しない。
- メニュー切替・幅変更・一覧へ戻る際の入力保持。別人の編集開始など入力を捨てる操作は確認する。
- 入力途中の追加/編集へ戻る専用ボタン。未反映の入力がある間はCSV操作へ進ませない。
- CSV書出し、UTF-8/Shift_JISを明示選択した読込み、事前検証、現在の下書きとの差分、削除対象の確認後の置換。
- 基本6名、多数・長い名前100名、登録前0名のサンプル切替。切替前に未反映入力と下書きの破棄を確認する。
- ワイドPCのグループ/一覧/詳細併置、iPad相当幅のグループ/一覧と詳細の上下配置、スマホの一覧/詳細切替。

「試作内で確定」はブラウザの現在ページのメモリ内だけで行う。再読込みでサンプル名簿に戻る。名簿・連絡先をlocalStorage/sessionStorageへ保存しない。認証、既存のconfig.js、Worker/D1/KV、外部フォント/CDNは使用せず、CSPのconnect-src 'none'でも通信を禁止する。

CSVの読み書きは既存の通信なし `js/services/csv.js` を再利用する。共通形式のタイトル/13列ヘッダ/既定ステータスを同サービスから公開し、書出し内容は維持した。試作の検証/置換は独立moduleで行い、既存管理画面のCSV取込み・保存処理は変更していない。

CSVは2MiB・2000名を試作内の上限とし、問題の表示は先頭100件程度に制限する。これはWorkerの入力上限仕様ではない。空CSV、不正な引用符/列数/必須値/連絡先、重複ID、グループ番号と名称の不整合、グループ内の順序重複を拒否する。エラーには物理行番号を表示し、不正行を黙って除外しない。

ID空欄は新規人員になることを警告する。CSVに含まれない既存人員の削除は氏名/ID一覧と確認チェックを必須にする。ステータス・業務時間・戻り時間・明日の予定・備考も置換対象として差分に出す。同一IDのCSV外属性は保持する。空グループはCSVに表せないため、その削除も差分対象になる。

試作は実拠点のステータス定義を取得しないため、CSVのステータス文字列を保持する。既存管理の取込みは未知のステータスを既定値に正規化するので、API接続時は実設定を使った検証を別途設計する。書出し時の数式対策による先頭アポストロフィは、再取込みで勝手に除去しない。

表示上のサンプル拠点/管理者は架空の文脈であり、権限検証の実装ではない。試作のグループIDは画面内の識別用で、共有D1に固定IDを導入するmigrationではない。

## 今回は対象外

「お知らせ・予定」「ツール」「在席表の設定」「拠点・アクセス」は移動先が分かる構成案のプレビューで、編集APIは接続していない。ドラッグによる移動、連絡先検索、閲覧用ソート、表示列選択、保存後の復元は未実装。CSVの追加/マージ方式は対象外で、現行同様に名簿全体の置換として扱う。

現行保存は空グループを保持しないため、試作でも空グループを確定成功扱いにしない。最初のメンバーを追加/移動するか、下書きグループを削除する必要がある。最後のグループ/全員の削除は試作対象外。

試作内にはサーバー側の競合・原子的保存・API部分成功の再現はまだない。本物の保存への接続はD01/D02/D03と連絡先の部分成功を保全する段階Cの後で行う。既存の管理画面と保存仕様は変更していない。
