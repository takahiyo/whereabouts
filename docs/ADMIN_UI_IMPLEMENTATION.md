# 管理GUIの再分類・イベント改善

更新: 2026-10-04。実装対象はdevの画面側。Worker、D1、KV、認証、Cronは変更しない。テストは全通信を差し替え、共有DBに書き込まない。

## 全タブの分類と配置

管理の初回表示は「メンバー・グループ」。再度開いた時は前の作業を保持する。主メニューは全端末で同じ5領域、その下に現在の領域の作業だけを表示する。既存の保存単位を変えず、関係の薄い設定を「基本」へ詰め込む構造を解消した。

| 領域 | 作業 | 今回の整理 | 次の設計課題 |
|---|---|---|---|
| メンバー・グループ | メンバー登録・編集、グループ・表示順、CSV取込・書出し | 初期表示。グループとメンバーは同じ「名簿の変更を保存」。狭い幅は項目名付きカード。CSVを基本設定から移動 | 統合名簿、差分確認、所属の一括移動、人員を失わないグループ削除。独立試作の保存基盤への接続はD01/D02/D03後 |
| お知らせ・イベント | イベント、お知らせ | 関連付けのある機能を隣接。イベント一覧をカード化し、期間/対象拠点/お知らせをラベル付き表示。公開と休暇固定をフォームでも編集 | お知らせの一覧/詳細編集の分離、検索、予約公開。予定のメンバー参照と名簿変更の関係を設計 |
| ツール | リンク・ツール | 表示設定、入力、操作ボタンの配色を外観に統一。狭い幅のタイトル/URL/操作を縦に整理 | 一覧と詳細の分離、リンク検索/分類、保存前のURL検証とWorker側の認可/検証 |
| 在席表の設定 | 表示項目・レイアウト、自動消去、印刷・PDF | 名称を利用者向けに整理。PDF出力を移動。項目構成/カード順/レイアウト入力もテーマに統一 | 表示結果のライブプレビュー、拠点共有設定と端末固有設定の区別、印刷の実機確認 |
| 拠点・アクセス | 拠点名・パスワード、拠点一覧・追加 | 拠点設定を移動。拠点一覧・追加の入口は既存superAdmin権限に限定 | 権限説明、拠点削除の影響確認。認証/パスワード/サーバー認可の既知課題は別変更 |

主メニュー・作業ボタン・見出し・説明・編集枠・操作・表・入力を6種の外観トークンで統一する。PCは一覧とイベントフォームを並べ、960px以下は縦に配置する。スマホでも機能を削らず、イベントの期間・対象拠点・休暇固定を読める配置にする。イベントの日付カテゴリー色は意味を持つため維持する。

同じ拠点で領域を往復・管理を開き直す際は、読込み済みの編集DOMを保持する。自動消去・表示項目・名簿・イベント・お知らせ・ツールが再取得で勝手に消えないようにした。明示的な再読込みは表示中の作業を対象とし、未保存の破棄を確認する。名簿はメンバー/グループが同じ原稿。画面の全編集を一括保存する機能は追加しない。

## イベントの修正

1. 未選択では入力表を開かず、選択を促す説明を表示する。以前に選んだ有効なIDがある場合だけ、プルダウンと詳細を同じIDで復元する。削除済みIDを先頭イベントで代用しない。未選択へ戻す操作も有効にする。
2. プルダウンの再生成でchange listenerが蓄積する問題を解消。定期更新後も利用者の選び直しは反映し、定期更新自体は編集途中のビットを上書きしない。関連するお知らせボタンの非表示クラスも整合させる。
3. 新規保存に既存APIが受け付けるクライアントIDを用意し、`{ok:true}`だけの応答でも保存した内容を表示できるようにする。公開/休暇固定を明示して保存し、更新時も保持する。成功した原稿を一覧・メインのイベントボタンへ反映し、直後のGETによる古いKV一覧で消さない。失敗時は入力を保持し、成功表示を行わない。作成の二重送信を防ぐ。
4. 表の強調を最初のtbodyからtableへの委譲に変更し、全グループへ適用。日付とON/OFFの背景を塗り潰さず、行/列を線、交点を枠で示す。ONにはチェックを表示する。
5. 日付列は32pxを基本とし、日付と曜日を縦に表示する。表を全幅に引き延ばさない。月見出しは日付列を広げず、短い期間では省略＋titleで表示する。タッチの行高さは44px。
6. 日付表は一つのTab入口から矢印で移動し、Enter/SpaceでON/OFFを切り替える。クリック/ドラッグ/タップも維持し、aria-pressedを更新する。ビット形式と明示的な保存操作は変更しない。
7. イベントカードの上下ボタンとドラッグによる並び替えは既存の保存APIを使う。表示/休暇固定の一覧操作は即時保存、フォーム操作は「作成/更新」で保存する。削除した最後のイベントもメインへ即時反映する。

保存後のローカル表示改善はサーバーのキャッシュ整合性を保証しない。別端末への反映、KVのnocache対応、定期更新との競合、イベント並び替えの複数リクエストの部分成功は共有基盤の残課題。schemaや新しいDBフィールドは追加しない。

## 検証と次の優先順位

`npm run check`、`npm test`、`npm run test:browser`を実行する。ブラウザの全外部通信を差し替え、イベントのAPIもメモリー上で応答する。

- 最初のイベントを保存して、古いGETが空でもメインボタンと一覧が表示される。
- 保存失敗で入力/キャッシュを保持。公開・休暇固定の変更を保持し、最後の削除でボタンが非表示になる。
- 未選択/復元/解除/関連お知らせ/再読込み後の選択が整合する。定期更新で未保存ビットを失わない。
- 3グループの強調、日付列の幅、色を塗り潰さない表現、矢印/Space操作を確認。明示保存のIDと全グループのビットを確認する。
- 管理の全作業を6テーマ×360/820/1280pxで巡回し、管理本文の横はみ出しとお知らせ/ツールのテーマ追従を確認する。通常在席表/独立管理試作/閲覧dialogの既存回帰も維持する。

次はdevで端末の使い勝手を確認し、iPad/iPhone Safari実機、キーボード表示時、長い氏名・多人数、多数のイベント、印刷を評価する。管理/イベントのfocus trap、未保存で閉じる確認、全画面contrastは未完了。独立試作の統合原稿/差分/保存を現行名簿へ接続する変更は、共有データ保全後に進める。既存管理全機能の保存方式を今回まとめて変更したものではない。
